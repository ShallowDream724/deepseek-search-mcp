# AI 搜索工具基准测试 · 2026-10-17

比较原生 `web.run`、AnySearch MCP、DeepSeek Search MCP 向 AI 代理返回的首轮检索证据。测试不调用语言模型生成最终答案，评分关注结果是否切题、能否追溯、是否满足日期/实体约束，以及摘录能否支持下一步核验。

下载仓库后用浏览器打开 [中文交互报告](report.html)。页面和图表无需联网；逐题来源链接仍需网络。可独立使用 [总分图](charts/overall.png)、[场景图](charts/categories.png)、[学术专项图](charts/academic-breakdown.png)、[来源质量图](charts/source-quality.png)。

## 本批结果

| 工具 / 路由 | 总体 | 学术 | 新闻时效 | 低证据来源比例 |
|---|---:|---:|---:|---:|
| 原生搜索 | 87.3 | 86.8 | 80.2 | 9.2% |
| DeepSeek Search | 78.8 | 78.2 | 73.3 | 29.5% |
| AnySearch：主实验路由 | 60.8 | 46.5 | 71.9 | 36.6% |
| AnySearch：学术改用通用路由（补测） | 68.5 | 65.7 | 保持主实验结果 | 未混算 |

这些是本批题目的量表分数，不是普遍能力排名。AnySearch 主实验对学术问题使用发现并记录的学术垂直路由；补测把同样30题全部改用通用路由，未按题择优。完整请求参数见 [cases.json](cases.json)。

DeepSeek 能检出当天消息，但结果仍混有转载、导购和未满足日期条件的页面。低证据来源比例统计的是质量评分不超过1的结果，不能当成“SEO作弊率”。原生搜索在这批任务中得到更多可直接引用的一手材料，但返回文本也更长。

## 样本与协议

- 74条查询：中文37、英文37；学术30、日常12、新闻时效16、技术与精确检索6、来源质量与SEO场景10。
- 222次主实验搜索、30次AnySearch通用路由补测、30次网页读取。原页抽查和修复验证另计，不混入这282次。
- 学术包含精确论文/DOI、DID方法、CRISPR综述、MIMIC数据、撤稿、重复性、现金转移试验、数字人文、气候证据、ImageNet，以及2026年10月新论文。
- 时效题包含当天DeepSeek Flash-1017与Search/Fetch、近72小时OpenAI公告、DevDay日期、NASA和CPI。部分事实锚点见 [freshness-anchors.json](freshness-anchors.json)，它们不是穷举正确答案集。
- 查询文本保持一致。评分只取前5条；AnySearch请求`max_results=5`，DeepSeek请求`count=5, need_content=false`。原生工具无法强制只返回5条，多余条目不评分。
- 主结果保留第一次调用，不用重试成功覆盖失败。基线MCP代码为 `aead844`。题集在A01试跑后按需求加入当日任务；量表没有随排名调整，未做外部预注册。

网页读取单列：普通HTML、长文档、中文站点、PDF、JSON、JavaScript页面、访问限制和不存在页面。原生能读本次arXiv PDF，另外两者失败；三个工具各有访问失败，不能由一次失败推断永久不支持整个格式。

## 评分与复核

每条结果记录相关性 `r`（0–2）、来源质量 `q`（0–3）、摘录可用性 `u`（0–2）；每次查询记录覆盖度 `c`（0–4）、约束满足 `k`（0–2）。

$$S=35\frac{\overline r}{2}+30\frac{\overline q}{3}+25\frac{c}{4}+10\frac{k}{2}$$

少于5条按实际条数算相关性与质量，覆盖度另反映缺口；空结果/调用失败为0。总体按查询等权，来源比例按实际结果数汇总。`u` 是独立诊断指标，不额外加入总分。高质量但不切题的原始论文仍可得到质量分，因此总分须连同直接相关率与覆盖度阅读。

评分代理阅读隐藏提供方名称、按题随机映射A/B/C的材料，通用路由补测为D组。标题、URL和摘录保留；超过2200字符时取前1600和后600字符，完整返回本地保存。格式特征仍可能暴露工具身份。这是AI评分和主代理抽查，不是人工评审或全面双重评分。

主复核纠正了政府子域判断、香农论文两部分、DOI在URL中被漏看、原厂维修文档被误识别、低证据与明确误导混淆等问题；其中维修文档再由另一评分代理独立复核。保存 [初始评分](reviews-initial.json)、[逐项修改](review-audit-log.json)、[最终评分](reviews-final.json)。原页访问失败的疑点保持待查，不直接指控假冒或操纵。

## 复现图表与重新采集

复现已有统计和图表需要Python 3.11+与matplotlib（本次3.9.2），不调用付费接口：

```bash
python benchmarks/2026-10-17-agent-search/aggregate.py
python benchmarks/2026-10-17-agent-search/build_report.py
```

中文字体优先使用系统微软雅黑、黑体或Noto Sans CJK。脚本不自动下载字体或浏览器。

[source-results.json](source-results.json) 保存结果标题、URL、排名和测量元数据，足以复现统计；异常长标题只保留首行并限140字符/22个空格分词，标记`title_truncated`；[report-data.json](report-data.json) 为展示数据。[evidence-manifest.json](evidence-manifest.json) 保存原始返回的SHA-256。网页全文和评分摘录不公开复制，**仅凭公开元数据无法独立重做全部内容评级**；需要重新采集并接受索引随时间变化。哈希证明文件一致性，不证明网页真实性。

重新采集DeepSeek需要先按项目README配置 `deepseek-search` MCP及密钥，再运行 `collect_deepseek.py` / `collect_fetch.py`。这些脚本跳过已有文件，避免无意覆盖原始记录；请在独立目录复制题集和脚本，进行新的运行。Fetch参数固定`max_chars=15000`。运行会产生官方API费用。

原生搜索和AnySearch通过Codex宿主实际工具调用采集，不存在本项目提供的通用HTTP替代端点。[collect_hosted.js](collect_hosted.js) 记录同样的工具请求和并发采集逻辑；需由有这些工具权限的宿主注入 `tools` 和结果保存回调，不能直接用普通Node进程获得原生搜索权限。原始请求参数也保留在题集中。

`normalize.py`把原始返回转成前5条并生成匿名评分包；`prepare_supplement.py`处理补测；`ingest_reviews.py`可从明确指定的本任务日志导入评分JSON。重新评分应产生新的初始评分和修订记录，不复用本批判断。

## 时延与适用边界

原生与AnySearch采集并发4，DeepSeek串行且间隔0.25秒；网络路径、缓存、工具调度均不同。图中的中位数/P90只描述本次运行，**不用于严格速度排名、吞吐能力或SLA推断**。字符量统计实际返回文本一次，不重复计structuredContent，也不是精确token数；原生可能返回超过5条，故其体量不可直接理解为每5条成本。

只有一次运行，查询存在中英文同主题关系，不报告显著性或置信区间。没有全网相关文档全集，不能报告真正的召回率。本次未测多轮代理成功率、动态浏览器交互、全部语种或付费性价比。不得把这份探索性报告当成经过独立第三方认证的排行榜。

## 测试中修复的问题

F07基线在重试后耗时92,138ms，错误消息没有具体原因。修复提交 `871c1e0` 增加共享总超时预算（默认45秒）、重试次数和耗时诊断，并保留取消与Retry-After语义。187项离线测试通过，包含stdio与HTTP传输。

[修复后的真实调用](fix-validation.json) 使用已安装Codex配置、临时把总预算设为15秒：搜索和文档读取成功；同一F07页面在15,013ms返回明确超时，服务端记录15,000ms。此验证单列，未改写基线失败，也未用修复后的结果替换主榜。
